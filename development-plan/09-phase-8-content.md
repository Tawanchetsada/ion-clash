### ขั้นที่ 1 · รวมข้อความไทยไว้ที่เดียว

**สร้าง** `src/config/messages.ts` — ไฟล์ข้อมูลล้วน ไม่มี React ไม่มี logic

```ts
export const MESSAGES = {
  error: {
    "E-CHARGE": "ประจุรวมสองข้างยังไม่เท่ากัน ลองตรวจจำนวนไอออนอีกครั้ง",
    "E-PAIR": "…", "E-PHASE": "…", "E-BALANCE": "…", "E-RATIO": "…", "E-SPECTATOR": "…",
  },
  success: { /* … */ },
  save: { /* idle / saving / saved / error */ },
  toast: { /* ปลดล็อก / import สำเร็จ / reset แล้ว */ },
  ui: { /* ปุ่ม หัวข้อ คำอธิบาย */ },
} as const;
```

**กติกา**

- ข้อความ error ทั้ง 6 รหัส **ต้องบอกหลักการที่ผิด ไม่บอกคำตอบ** (ข้อห้ามข้อ 6 ใน `CLAUDE.md`)
- `aria-label` ของไอออนและชื่อไทยของสารประกอบ **ไม่ต้องย้ายมาที่นี่** — มันสร้างจากข้อมูลมีโครงสร้างใน `src/presentation/speech.ts` แล้ว ซึ่งถูกกว่า
- ย้ายข้อความที่ Phase 5–7 ฝังไว้ใน component มาที่นี่ทีละตัว แล้วให้ component รับเป็น prop หรือ import จาก `src/config/`

**เพิ่มเทสต์ใน `src/architecture.test.ts`**

```
it("ไม่มีข้อความไทยฝังใน src/components/ — ต้องมาจาก prop หรือ src/config/messages.ts")
```
สแกนไฟล์ใน `src/components/**` (ไม่รวม `*.test.tsx`) หา literal ที่มีอักขระไทย (`/[฀-๿]/`)
**ยกเว้นรายการที่อนุญาตอย่างชัดเจน** เช่นข้อความสถานะสั้น ๆ ที่เป็นส่วนหนึ่งของ component จริง — ถ้ามี ให้ประกาศเป็น allowlist ในเทสต์พร้อมเหตุผลกำกับแต่ละรายการ ไม่ใช่ปิดกฎทิ้ง

**สร้าง** `src/presentation/solubility.ts`

export type SolubilityRuleView = {

### ขั้นที่ 3 · หน้า `/knowledge` — 4 หัวข้อ

รูปแบบหน้า: accordion 4 หัวข้อ เปิดทีละอัน มีปุ่ม **เริ่มเล่นเลย** ค้างอยู่ด้านล่าง
ใช้ `<details>/<summary>` หรือปุ่มที่มี `aria-expanded` — **ห้ามทำ accordion ด้วย `div` เปล่า**

#### หัวข้อ 1 · การแตกตัวของสารละลาย

- สารประกอบไอออนิกเมื่อละลายน้ำจะแตกตัวเป็นไอออนบวกและไอออนลบ
- ตัวอย่าง `NaCl(aq) → Na⁺(aq) + Cl⁻(aq)`
- ตัวอย่างที่มีสัมประสิทธิ์ `CaCl₂(aq) → Ca²⁺(aq) + 2Cl⁻(aq)`
- ย้ำว่าไอออนหลายอะตอมอย่าง NO₃⁻ **ไม่แตกออกอีก** ยังอยู่ทั้งก้อน
- **สารที่ไม่ละลายน้ำจะไม่แตกตัว** คงเขียนเป็นสูตรทั้งก้อนพร้อม `(s)`

> สูตรทุกตัวในหน้านี้ render ด้วย `EquationView` ไม่ใช่พิมพ์ตัวห้อยเป็นอักขระ Unicode ในสตริง
> (มีเทสต์ห้าม `dangerouslySetInnerHTML` ทั้ง `src/` อยู่แล้ว)

#### หัวข้อ 2 · กฎการละลาย

ตารางจาก `solubilityTableView()` ในขั้นที่ 2 พร้อมกฎครอบ **เกลือของ Na⁺ K⁺ NH₄⁺ ละลายน้ำทั้งหมด**

#### หัวข้อ 3 · ไอออนผู้ชม

- นิยาม: ไอออนที่อยู่ทั้งสองข้างของสมการโดยไม่เปลี่ยนแปลง
- แสดงตัวอย่างเต็มสามชั้น: โมเลกุล → ไอออนิกสมบูรณ์ → ไอออนิกสุทธิ
- ย้ำว่าตัดได้ต่อเมื่อ **ชนิด ประจุ สถานะ และจำนวนเท่ากันทั้งสองข้าง**

#### หัวข้อ 4 · การดุลสมการ

- อะตอมทุกธาตุต้องเท่ากันสองข้าง · ประจุรวมต้องเท่ากันสองข้าง
- สัมประสิทธิ์ต้องเป็นอัตราส่วนต่ำสุด — อธิบายว่าทำไม 2:2:2:2 ผิดถ้า 1:1:1:1 ใช้ได้

**ตัวอย่างสมการทุกตัวในหน้านี้ต้องไม่ใช่ด่านจริงในชุด 50 ด่าน** — เช็กด้วยตาแล้วบันทึกไว้ในเอกสารเฟสว่าเช็กแล้ว

### ขั้นที่ 4 · หน้า `/how-to-play` — กดเล่นได้จริง

**ไม่ใช่หน้าอ่านอย่างเดียว** การอธิบายการลากวางด้วยข้อความไม่เวิร์ก

- ใช้ตัวอย่าง **ที่ไม่ใช่ด่านจริง** — spec แนะนำ `BaCl₂ + Na₂SO₄`
  ก่อนใช้ ให้ `grep` ใน `src/data/levelSeeds.ts` ยืนยันว่าคู่นี้ไม่อยู่ในชุด 50 ด่าน **แล้วเขียนเทสต์คุมไว้**
- แสดงทีละขั้นให้ตรงกับ 5 ขั้นของเกมจริง
- ในขั้นลากวาง ให้ผู้เล่นลองลากจริง มีลูกศรชี้และข้อความบอก — ใช้ `usePlacement` ตัวเดียวกับเกมจริง
- บอกครบทั้งสามวิธี: ลาก · แตะสองครั้ง · คีย์บอร์ด
- อธิบายความหมายของสีทั้งสี่ (กรม/น้ำเงิน/เขียว/ทอง) พร้อมตัวอย่างการ์ดจริง
- อธิบายว่าคำใบ้หักคะแนนเท่าไร และดาวคิดยังไง — **อ่านค่าจาก `SCORING`** ไม่ใช่พิมพ์เลขซ้ำ

> ตัวอย่างในหน้านี้สร้างจาก `buildCompoundById` + `buildReaction` ของจริง ไม่ใช่ข้อมูล hard-code
> ถ้าวันหน้ากฎการละลายเปลี่ยน ตัวอย่างจะเปลี่ยนตามหรือพังให้เห็น ไม่ใช่สอนผิดเงียบ ๆ

### ขั้นที่ 5 · ขัดสำนวนคำใบ้ 150 ข้อ

คำใบ้มีครบแล้วจากแม่แบบ D-05 งานที่เหลือคือ **ทำให้อ่านแล้วเป็นภาษาคน และต่างกันตามช่วงความยาก**

| ระดับ | แม่แบบปัจจุบัน | ต้องปรับอะไร |
|---|---|---|
| 1 | "ปฏิกิริยานี้เกิดจากการแลกคู่…" | เหมือนกันทั้ง 50 ด่าน — ให้ต่างกันตามช่วง 5 ช่วง (ง่าย/พื้นฐาน/ปานกลาง/ยาก/ท้าทาย) เช่นช่วงยากไม่ต้องอธิบายพื้นฐานซ้ำ |
| 2 | "ลองพิจารณาว่า{ไอออนบวก}จับกับ…" | ตรวจว่าชื่อไทยอ่านลื่นทุกตัว โดยเฉพาะ `Fe²⁺` vs `Fe³⁺` ที่ต้องแยกกันได้ |
| 3 | "กฎ: {descriptionTh}…" | ด่านที่ต้องดุล ให้เปลี่ยนระดับ 3 เป็นคำใบ้เรื่องสัมประสิทธิ์แทน (ดูแม่แบบล่าง) |

**แม่แบบคำใบ้สัมประสิทธิ์** (ใช้แทนระดับ 3 เฉพาะด่านที่ `coefficients` ไม่ใช่ 1:1:1:1)

> ประจุของ{ไอออน}เป็น {n} จึงต้องใช้{ไอออนอีกตัว}กี่ตัวจึงจะได้ประจุรวมเป็นศูนย์

**แก้ที่ `generateHints` ใน `src/data/buildLevel.ts` เท่านั้น** — ห้ามเขียนคำใบ้รายด่านลง `levelSeeds.ts`
(ข้อห้ามข้อ 2 ใน `CLAUDE.md`: seed มีแค่ `id` `difficulty` และไอออนสองคู่)

**ข้อห้ามเด็ดขาด** คำใบ้ทุกข้อต้องไม่มีสูตรของผลิตภัณฑ์ตะกอนอยู่ในข้อความ — เทสต์ "กฎ 11" คุมอยู่แล้ว รันซ้ำทุกครั้งที่แก้สำนวน

**เพิ่มเทสต์**

- คำใบ้ระดับ 1 ของด่านช่วง "ง่าย" กับช่วง "ท้าทาย" ต้องไม่เป็นสตริงเดียวกัน
- ด่านที่ต้องดุลทุกด่าน คำใบ้ระดับ 3 ต้องมีคำว่า "ประจุ" หรือ "สัมประสิทธิ์"

### ขั้นที่ 6 · แผงกฎการละลายระหว่างเล่น

เพิ่มปุ่มเปิดตารางกฎการละลายในหน้าเล่นเกม **โดยไม่หักคะแนน** เพราะการเปิดตำราดูกฎไม่ใช่การขอเฉลย

- ใช้ `Dialog` ที่มีอยู่แล้ว (focus trap + Escape + คืน focus ครบ)
- แสดงตารางเดียวกับหน้า `/knowledge` ผ่าน `solubilityTableView()`
- **ห้ามไฮไลต์แถวที่เกี่ยวกับด่านปัจจุบัน** เพราะนั่นคือการเฉลย
- **ห้ามยิง `USE_HINT`** — ปุ่มนี้ไม่ผ่าน reducer เลย เป็นแค่ UI

> ข้อนี้ไม่มีใน spec เดิม แต่จำเป็นจริง เพราะนักเรียน ม.4 ยังจำกฎการละลายไม่ได้
> ถ้าไม่มีตารางให้ดู เกมจะกลายเป็นการทดสอบความจำแทนการทดสอบความเข้าใจ ซึ่งขัดกับเป้าหมายการวิจัย
> **บันทึกข้อนี้ลง `docs/assumptions.md`** เพราะเป็นการเพิ่มจาก spec

### ขั้นที่ 7 · ส่งให้อาจารย์ตรวจ

- รวมเนื้อหา 4 หัวข้อ + ตารางกฎ + ตัวอย่างคำใบ้ทั้ง 3 ระดับของด่านตัวแทน 5 ด่าน (ด่านละช่วง) เป็นเอกสารเดียว
- ระบุคำถามที่ต้องการคำตอบให้ชัด ไม่ใช่ส่งไปเฉย ๆ (ดู A-02 ใน `99-open-questions.md`)
- **ถ้ายังไม่ได้ลายเซ็น ปิดเฟสได้** แต่ต้องขึ้นสถานะเป็น "⏳ โค้ดเสร็จ · รอตรวจ" เหมือน Phase 2 ไม่ใช่ ✅

## Definition of Done

- [ ] `/knowledge` มีเนื้อหาครบ 4 หัวข้อ ไม่มี placeholder เหลือสักบรรทัด
- [ ] ตารางกฎการละลายในหน้านี้สร้างจาก `solubility.ts` — พิสูจน์ด้วยเทสต์ที่นับจำนวนแถว
- [ ] `/how-to-play` ลากวางตัวอย่างได้จริงทั้ง 3 วิธี และตัวอย่างไม่ใช่ด่านจริง (มีเทสต์คุม)
- [ ] คำใบ้ครบ 150 ข้อ ไม่มีข้อความว่าง และระดับ 1 ต่างกันตามช่วงความยาก
- [ ] ด่านที่ต้องดุล มีคำใบ้เรื่องสัมประสิทธิ์
- [ ] เทสต์ "กฎ 11 · คำใบ้ไม่มีสูตรตะกอน" ยังผ่านครบ 50 ด่าน
- [ ] แผงกฎการละลายเปิดได้จากหน้าเล่นเกม ปิดด้วย Escape ได้ และ **ไม่หักคะแนน**
- [ ] ข้อความไทยไม่ฝังใน `src/components/` — มีเทสต์สถาปัตยกรรมคุม
- [ ] อ่านทั้ง `/knowledge` และ `/how-to-play` ออกเสียงจริงหนึ่งรอบ แล้วไม่มีประโยคที่สะดุด

## กับดักที่ต้องระวัง

| กับดัก | ผลที่ตามมา |
|---|---|
| พิมพ์ตารางกฎการละลายด้วยมือ | วันที่แก้กฎในโค้ด เนื้อหาสอนจะขัดกับพฤติกรรมเกมทันที และไม่มีใครรู้ |
| ใช้ด่านจริงเป็นตัวอย่างใน `/how-to-play` | เฉลยด่านนั้นให้ฟรี |
| เขียนคำใบ้ระดับ 3 เป็นการเฉลย | ผู้เล่นจ่าย 30 คะแนนแล้วได้คำตอบ กลายเป็นซื้อเฉลย ไม่ใช่การเรียนรู้ |
| เขียนคำใบ้รายด่านลง `levelSeeds.ts` | ผิดข้อห้ามข้อ 2 — seed ต้องมีแค่ 4 ฟิลด์ |
| ฝังข้อความไทยใน component | ตรวจภาษาไม่ได้ และอาจารย์ตรวจไม่ทั่ว |
| ไฮไลต์แถวกฎที่ตรงกับด่านปัจจุบัน | กลายเป็นเฉลยฟรีที่ไม่หักคะแนน |
| ลืมว่า ม.4 ยังจำกฎการละลายไม่ได้ | เกมวัดความจำแทนความเข้าใจ ผลวิจัยเพี้ยน |
| พิมพ์ตัวเลขคะแนน/ดาว ซ้ำในหน้าอธิบาย | วันที่ปรับ `SCORING` หลังการทดลองนำร่อง หน้าอธิบายจะโกหก |

## พิธีปิดเฟส

1. `npm run lint && npm run typecheck && npm test && npm run build` ผ่านครบ 4
2. `npm run test:e2e` ยังผ่าน
3. เขียนบล็อกสถานะต้นไฟล์นี้ — ระบุด้วยว่าเนื้อหาส่งให้อาจารย์วันไหน และรอตอบเรื่องอะไรบ้าง
4. อัปเดต `development-plan/README.md` · `CLAUDE.md` · และ **เพิ่มรายการแผงกฎการละลายลง `docs/assumptions.md`**
5. commit + push แล้วรอ CI เขียว
