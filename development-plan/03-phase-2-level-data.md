**ที่ยังไม่เสร็จ:** ยังไม่ได้ส่ง `docs/chemistry-review.md` ให้อาจารย์ที่ปรึกษาเซ็น ตาม DoD ข้อสุดท้าย

อาจารย์ตัดสินเป็นพิเศษ" (D-15) และตารางกฎการละลาย 11 ข้อต่อท้ายตามแผน

### ต่างจากแผน — `hints` ไม่ได้เก็บในไฟล์ seed

แผนเดิมให้ `LevelSeed` มีฟิลด์ `hints: [string, string, string]` ที่พิมพ์มือ 150 ข้อความ แต่
`development-plan/09-phase-8-content.md` (D-05) ระบุชัดว่าการเขียนคำใบ้จริงเป็น**งานเขียนเนื้อหา
แยกต่างหาก** ของ Phase 8 ("ควรกันเวลาไว้ต่างหากและอย่าประเมินต่ำ") — ถ้าบังคับให้ Phase 2 ต้อง
authored 150 ข้อความก่อน จะบล็อก phase นี้โดยไม่จำเป็น

**ทางแก้:** ย้ายการสร้างคำใบ้เข้าไปใน `buildLevel()` แทน โดยเติมแม่แบบที่ D-05 อนุมัติไว้แล้วด้วย
ข้อมูลโครงสร้างที่ Phase 1 คำนวณอยู่แล้ว — ระดับ 2 ใช้ `getIon(precipitate.cationId).nameStemTh`
(ไอออนบวกตัวการที่ทำให้เกิดตะกอน) ระดับ 3 ใช้ `explainPhase(...).rule.descriptionTh` (ข้อความกฎ
การละลายข้อที่ตัดสินด่านนี้จริง) ทั้งสองอ่านจาก field ที่มีอยู่แล้ว ไม่ได้เดาเนื้อหาใหม่ จึงไม่ขัดข้อห้าม
เรื่องห้ามเดาสมการ และ**รับประกันว่าไม่มีสูตรตะกอนหลุดในคำใบ้**เพราะไม่เคยเรียก `formulaToPlainText`
กับ `precipitate.formula` เลย (กฎ 11 ผ่านโดยอัตโนมัติ ไม่ต้องเขียน test แยกตรวจทีละคำ)

**ผลต่อการทำงาน:** `LevelSeed` เหลือแค่ 4 ฟิลด์ (`id`, `difficulty`, `reactantA`, `reactantB`) ไม่มี
`hints` — Phase 8 จะเห็นคำใบ้ที่ใช้งานได้จริงอยู่แล้วสำหรับทั้ง 150 ช่อง (50 ด่าน × 3 ระดับ) ตั้งแต่วันแรก
และสามารถ**ปรับสำนวนเฉพาะจุด**ได้ในภายหลังโดยไม่ต้องแก้ `buildLevel()` เช่น เพิ่ม override field ถ้า
ต้องการ ณ วันนั้น — Phase 2 นี้ไม่ได้ทำ speculative override infrastructure ไว้ล่วงหน้าเพราะยังไม่มี
requirement จริง

### ต่างจากแผน — `LevelSeed.reactantA/B` ใช้ `string` ไม่ใช่ `IonId` literal union

แผนเดิมอ้างถึง type `IonId` ที่ไม่เคยนิยามไว้จริง ตัดสินใจไม่สร้าง literal union ซ้ำจากทะเบียน 22
ไอออนใน `ions.ts` เพราะจะกลายเป็นข้อมูลซ้ำที่ต้อง sync มือสองที่ — ใช้ `string` ธรรมดาแทน โดยพึ่ง
`getIon()` ที่ throw เมื่อพิมพ์ผิดชื่อ ionId บวกกับ `levels.test.ts` ที่วนตรวจครบทั้ง 50 ด่านทุกครั้งที่
รัน CI เป็นตาข่ายนิรภัยแทน — พิมพ์ผิดจะ fail ทันทีตอน build เพราะ `levels.ts` เรียก `buildLevel()`
ที่ module scope

### ยืนยันแล้ว — เกณฑ์ difficulty ที่แก้ตามที่บันทึกไว้ตอนวางแผน Phase 1 ใช้ได้จริง

`expectedDifficulty(id)` ตรวจตามช่วงเลขด่าน (1-10=easy, ..., 41-50=challenge) บวกเงื่อนไขเสริมว่า
ด่าน 01-10 ต้องมีประจุ ±1 ทุกไอออนและสัมประสิทธิ์ 1:1:1:1 ทั้งหมด — รันกับข้อมูลจริงทั้ง 50 ด่านแล้ว
ผ่านทุกด่านตั้งแต่ครั้งแรก ยืนยันว่าข้อสรุปตอนวางแผน Phase 1 ถูกต้อง

### ตรวจอัตราส่วนสัมประสิทธิ์ที่ยากที่สุดกับตัวเลขในตารางแผนแล้ว

ด่าน 13, 35, 36, 39, 42, 50 ให้อัตราส่วนตรงกับตารางในข้อ 2.2 เป๊ะ ด่าน 40 ให้ตัวเลขชุดเดียวกันแต่
`productA`/`productB` สลับตำแหน่งกับที่ตารางเขียนไว้ (เพราะ `crossExchange` จับคู่ตาม cation ของ
reactantA เสมอ ไม่ได้จับคู่ตามที่ตะกอนมาก่อนหรือหลัง) — ไม่กระทบความถูกต้องทางเคมี เพราะ
`precipitateOf`/`aqueousProductOf` ค้นหาตะกอนจากทั้งสองช่องอยู่แล้ว ตรวจแล้วว่าสมการไอออนิกสุทธิ
ของด่าน 40 ลดถูกต้องเหลือ `Ba²⁺ + SO₄²⁻ → BaSO₄(s)` ตรงกับตัวอย่างที่อธิบายไว้ในกฎข้อ 12 พอดี

### เปลี่ยนโจทย์ด่าน 28 และ 29 ให้ตรงกับนิยามของช่วง `medium`

จากที่บันทึกไว้ว่าเกณฑ์ difficulty ชนกับป้าย 7 ด่าน ผู้ใช้ตัดสินให้**แก้ที่โจทย์** สำหรับด่าน 28-29
แทนที่จะยอมรับความไม่ตรงกัน (ส่วนด่าน 35-39 ยังใช้วิธีเดิม คือยึดช่วงเลขด่านเป็นเกณฑ์)

| ด่าน | เดิม | ใหม่ | อัตราส่วน |
|---|---|---|---|
| 28 | Ca(NO3)2 + Na2CO3 -> CaCO3 | MgSO4 + 2NaOH -> Mg(OH)2 + Na2SO4 | 1:2:1:1 |
| 29 | Ba(NO3)2 + Na2CO3 -> BaCO3 | Fe(NO3)2 + 2NaOH -> Fe(OH)2 + 2NaNO3 | 1:2:1:2 |

ตรวจแล้วว่า**ไม่มีเนื้อหาหาย** CaCO3 กับ BaCO3 ยังอยู่ที่ด่าน 15, 16, 17 · ไอออนทั้ง 22 ตัวยังถูกใช้ครบ ·
ตะกอนยังมี 29 ชนิด · เทสต์ทั้ง 627 ผ่านเหมือนเดิม · **เลข id ไม่ถูกแตะต้อง** ตามข้อห้ามเรื่องไฟล์เซฟ

> สมการสองด่านนี้ผู้พัฒนาเลือกเอง ไม่ได้อยู่ในร่างชุดแรก จึงทำเครื่องหมายไว้ใน
> `docs/chemistry-review.md` หัวข้อ 2 ให้อาจารย์ตรวจเป็นพิเศษ

### เพิ่มจากแผน — `getLevel(id)`

เพิ่ม helper คืนด่านตาม id เดียว (throw ถ้าไม่พบ) เพราะ Phase 4 (game state) และ Phase 6
(UI ด่าน) ต้องใช้แน่ ๆ และเขียนตอนนี้ง่ายกว่ากลับมาแก้ทีหลัง

### ปัญหาที่เจอ — lockfile ขาด optional deps ของ Linux ซ้ำรอย Phase 0

การรัน `npm install --save-dev tsx` บน Windows ทำให้ npm **ตัดรายการ optional dependency ที่เป็น
ของ Linux ออกจาก lockfile** (`@emnapi/core`, `@emnapi/runtime` หายไป เหลือแต่ `wasi-threads`)
CI จึงพังที่ขั้น `npm ci` ด้วย `Missing: @emnapi/runtime@1.11.3 from lock file` — เป็นข้อผิดพลาด
**ตัวเดียวกับที่เจอใน Phase 0** เป๊ะ

**แก้:** `rm -rf node_modules package-lock.json && npm install` (regenerate รวดเดียว) แล้วยืนยันด้วย
`npm ci --dry-run` ซึ่งตรวจ sync ระหว่าง package.json กับ lockfile แบบเดียวกับที่ CI ทำ

> **บทเรียนที่ต้องจำ:** บน Windows ห้ามเชื่อ lockfile ที่ได้จาก `npm install` แบบเพิ่มทีละแพ็กเกจ
> ทุกครั้งที่เพิ่ม/ลบ dependency ต้อง regenerate ทั้งไฟล์ แล้วรัน `npm ci --dry-run` ก่อน push
> ไม่งั้น CI จะพังซ้ำเรื่อย ๆ โดยที่เครื่องตัวเองรันผ่านหมด

## 2.1 หลักการ: เก็บให้น้อยที่สุด แล้วคำนวณส่วนที่เหลือ

spec เสนอ type `IonClashLevel` ที่มีทั้ง `coefficients`, `reactantIonInstances`, `productIonInstances`, `spectatorIonIds`, `netIonic` ซึ่งถ้าเขียนมือครบ 50 ด่านจะยาวหลายพันบรรทัดและผิดง่ายมาก

**แผนนี้เก็บเฉพาะข้อมูลที่คำนวณไม่ได้** แล้วให้ Phase 1 คำนวณส่วนที่เหลือตอนโหลด

```ts
export type LevelSeed = {
  id: number;                                   // 1..50 คงที่ตลอดไป
  difficulty: 'easy' | 'basic' | 'medium' | 'hard' | 'challenge';
  reactantA: { cation: IonId; anion: IonId };
  reactantB: { cation: IonId; anion: IonId };
  hints: [string, string, string];              // 3 ระดับตาม D-05
};

export function buildLevel(seed: LevelSeed): BuiltLevel;
```

`buildLevel` คำนวณให้ทั้งหมด: สูตรสารตั้งต้น · ผลิตภัณฑ์จากการแลกคู่ · สถานะ aq/s จากตารางกฎ · สัมประสิทธิ์จากการดุล · ion instances · ไอออนผู้ชม · สมการสุทธิ

**กำไรที่ได้:** แก้กฎการละลายที่เดียว ด่านทั้ง 50 อัปเดตตาม · เพิ่มด่านใหม่เขียนแค่ 5 บรรทัด · เป็นไปไม่ได้ที่ข้อมูลจะขัดแย้งกันเอง

> `id` คือตัวตนถาวร ห้ามเปลี่ยนเลขเมื่อสลับลำดับในไฟล์ เพราะไฟล์ save ของนักเรียนอ้างอิงเลขนี้

**เกณฑ์ตรวจระดับความยากอัตโนมัติ — ⚠️ แก้แล้ว ดูข้างล่าง**

เกณฑ์ที่ร่างไว้เดิมเป็นแบบนี้

| ระดับ | เงื่อนไข |
|---|---|
| `easy` | ประจุทุกไอออนเป็น ±1 และสัมประสิทธิ์ทุกตัวเป็น 1 |
| `basic` | มีประจุ ±2 และสัมประสิทธิ์สูงสุดไม่เกิน 2 |
| `medium` | ต้องมีวงเล็บในสูตรผลิตภัณฑ์ตะกอน |
| `hard` | มีประจุ ±3 หรือสัมประสิทธิ์สูงสุดตั้งแต่ 3 ขึ้นไป |
| `challenge` | สัมประสิทธิ์สูงสุดตั้งแต่ 6 หรือมี PO4 3- |

### ปัญหาที่พบตอนวางแผน Phase 1 — เกณฑ์นี้ชนกับป้ายที่กำหนดไว้ 7 ด่าน

ลองไล่เกณฑ์ข้างบนกับตารางด่านทั้ง 50 (ตรวจจาก `challenge` ลงมา `easy`) ตรง 43 ด่าน **ขัดกัน 7 ด่าน**

| ด่าน | ป้ายที่กำหนด | เกณฑ์คำนวณได้ | เพราะ |
|---|---|---|---|
| 28, 29 | `medium` | `basic` | CaCO3 / BaCO3 ไม่มีวงเล็บ ประจุ ±2 สัมประสิทธิ์ 2 — **แก้แล้วโดยเปลี่ยนโจทย์ ดูข้างล่าง** |
| 35, 36 | `hard` | `challenge` | สัมประสิทธิ์สูงสุด = 6 เข้าเงื่อนไข challenge |
| 37, 38, 39 | `hard` | `basic` | Fe2+/Ag+ ไม่มีประจุ ±3 และสัมประสิทธิ์ไม่ถึง 3 |

**สาเหตุ:** spec บังคับว่าหน้าเลือกด่านจัดกลุ่มตาม**ช่วงเลขด่าน** (01-10 ง่าย, 11-20 พื้นฐาน, 21-30 ปานกลาง, 31-40 ยาก, 41-50 ท้าทาย) กลุ่มละ 10 ด่านเป๊ะ ดังนั้น `difficulty` คือ**ป้ายเชิงหลักสูตรตามตำแหน่งในลำดับการเรียน** ไม่ใช่ค่าที่คำนวณจากความซับซ้อนของสูตร ถ้าคำนวณเอาจริง กลุ่มจะเบี้ยว (13 basic, 8 medium) แล้วหน้าเลือกด่านพัง

ด่าน 37-39 อยู่ช่วง `hard` เพราะ**แนวคิด**ยาก (Fe2+ เทียบ Fe3+ ให้ตะกอนคนละสูตร) ไม่ใช่เพราะเลขยาก ซึ่งตรงกับที่ spec เขียนว่าช่วง 31-40 คือ "โลหะแทรนซิชันหลายเลขออกซิเดชัน"

### เกณฑ์ที่ใช้จริง แทนของเดิม

1. `difficulty` ต้องตรงกับช่วงเลขด่าน — id 1-10 = `easy`, 11-20 = `basic`, 21-30 = `medium`, 31-40 = `hard`, 41-50 = `challenge`
2. คงเงื่อนไขที่ load-bearing จริงไว้ข้อเดียว: **ด่าน 01-10 ต้องมีประจุ ±1 ทุกไอออนและสัมประสิทธิ์เป็น 1 ทั้งหมด** เพราะช่วงนี้ต้องให้ผู้เรียนโฟกัสแนวคิดแลกคู่โดยไม่มีการดุลมากวน

> ไม่ต้องแก้ตารางด่าน ไม่ต้องสลับเลขด่าน — แก้เฉพาะกฎ validation ข้อ 9
> **ยังควรถามอาจารย์** ว่าด่าน 28-29 ซึ่งความซับซ้อนเท่ากับด่าน 15-17 แต่ถูกจัดเป็น `medium` นั้นรับได้ไหม หรืออยากสลับกับด่านอื่น — เพิ่มลงใน `docs/chemistry-review.md`

**กฎข้อ 12 อธิบาย** สมการโมเลกุลกับสมการสุทธิลดอัตราส่วนแยกกัน ตัวอย่างด่าน 40

```
โมเลกุล:        Al2(SO4)3 + 3BaCl2 -> 3BaSO4 + 2AlCl3      (อัตราส่วนต่ำสุดแล้ว)
ไอออนิกสมบูรณ์:  2Al3+ + 3SO4 2- + 3Ba2+ + 6Cl- -> 3BaSO4(s) + 2Al3+ + 6Cl-
ตัดผู้ชม:        3Ba2+ + 3SO4 2- -> 3BaSO4(s)
สุทธิที่ถูกต้อง:   Ba2+ + SO4 2- -> BaSO4(s)                  (ต้องหารด้วย 3 อีกชั้น)
```

ด่านที่เข้าข่ายนี้คือ 35, 36, 40 และ 50 ถ้าลืมลดขั้นสุดท้าย ผู้เรียนจะเห็นสมการสุทธิผิดรูปแบบที่ตำราสอน

> กฎข้อ 11 สำคัญกว่าที่คิด เพราะคนเขียนคำใบ้เผลอพิมพ์ AgCl ลงไปได้ง่ายมาก แล้วเกมก็เฉลยคำตอบให้ฟรี
