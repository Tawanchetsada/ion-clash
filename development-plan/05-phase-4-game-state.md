### งานค้างจากเฟสก่อนที่ยกมาทำในเฟสนี้

**1. `instanceId` ยังไม่มีใครสร้าง** — D-21 ตัดสินไว้ตั้งแต่ Phase 3 แต่ไม่มีไฟล์ไหนผลิต id จริง
เฟสนี้เพิ่ม `instances.ts` ที่คำนวณ id จากข้อมูลด่านล้วน ๆ พร้อมเทสต์ว่าสร้างสองครั้งได้ชุดเดิมเป๊ะ
ทั้ง 50 ด่าน รูปแบบคือ `L{levelId}:react:{a|b}:{cat|an}` · `L{levelId}:slot:{0..3}` ·
`L{levelId}:ci:{l|r}:{ion|cpd}:{id}` — มี `levelId` นำหน้าเพื่อให้ checkpoint ของด่านอื่น
match ไม่ติด แทนที่จะวางการ์ดผิดด่านแบบเงียบ ๆ

**2. checkpoint ไม่เก็บ `errorsByCode`** — schema ของ Phase 3 เก็บแค่ `wrongAttempts`
ยอดรวม ผลคือ refresh กลางด่านแล้วยอดรวมรอดแต่รายละเอียดหาย กลายเป็น `wrongAttempts` = 5
ในขณะที่ผลรวมรายรหัส = 2 ซึ่งขัดกันเองและย้อนกลับไปเก็บไม่ได้ **แก้ตอนนี้ฟรี** เพราะ save v1
ยังไม่เคยถึงมือใคร (ยังไม่มี UI) และ `normalizeSave` ซ่อมไฟล์ที่ขาดฟิลด์อยู่แล้ว จึงไม่ต้องเขียน migration

> **Zod v4:** `z.record(z.enum(...), ...)` บังคับให้มีครบทุกคีย์และปฏิเสธคีย์แปลกปลอม
> (ต่างจาก v3) ยิง probe ยืนยันก่อนเขียนจริง — พฤติกรรมนี้เป็นสิ่งที่ต้องการพอดี
> เพราะ `normalizeCheckpoint` เติมคีย์ที่ขาดให้ครบก่อนเสมอ

**3. เอกสารบอกว่าด่าน 01–10 ข้ามขั้นดุล แต่ข้อมูลจริงมี 13 ด่าน** — ตรวจสัมประสิทธิ์จริงทั้ง
50 ด่านแล้วพบว่า **ด่าน 1–10, 18, 19 และ 38** เป็น 1:1:1:1 ถ้า hard-code `id <= 10`
ตามที่ข้อ 4.1 เขียน สามด่านหลังจะโผล่ช่องกรอกที่ทุกช่องตอบ 1 ซึ่งไม่มีอะไรให้เรียนรู้และขัด D-04
→ `needsBalancing()` อ่านจากข้อมูลด่าน มีเทสต์ล็อกรายชื่อทั้ง 13 ด่านไว้
(สัมประสิทธิ์สูงสุดในชุดคือ 6 จึงไม่ชนเพดาน 1–9 ของช่องกรอกตามสเปก)

### ข้อขัดแย้งระหว่างเอกสารสองจุด ที่ตัดสินไว้แล้ว

**E-PHASE ยิงไม่ได้ในเฟสนี้ — โดยตั้งใจ** UI PDF หน้า 09 แสดงขั้น `validateProducts`
เป็นหน้าเฉลยผลล้วน ๆ ระบบแยกเองว่าตัวไหน "เกิดตะกอน" ตัวไหน "ยังคงอยู่ในสารละลาย"
แล้วมีปุ่มไปขั้นต่อไปอย่างเดียว ตรงกับตาราง state machine ในสเปกที่ให้ event เดียวคือ
`CONFIRM_PRODUCTS` ผู้เล่นจึงไม่เคยประกาศสถานะการละลายเอง
guard `claimedPhase` ในโดเมนยังอยู่ครบและทดสอบแล้ว เผื่อ Phase 6/7 เพิ่มขั้นให้ผู้เล่นชี้เอง
ว่าตัวไหนตกตะกอน ซึ่งจะเป็นการเพิ่ม event ไม่ใช่รื้อโครง

**คำใบ้ของด่าน 41–50** — ตารางระดับความยากในสเปกเขียนว่าช่วงนี้ "ลดคำใบ้" แต่ D-05
กำหนด 3 ระดับเท่ากันทุกด่าน และ `buildLevel()` ผลิต 3 ข้อครบทั้ง 50 ด่านไปแล้ว
แก้โดยให้โควตาคือ `level.hints.length` ไม่ใช่เลข 3 ที่ตายตัว — วันที่ Phase 8 (เจ้าของ
เนื้อหาคำใบ้) ตัดสินให้ด่านท้าทายมี 2 ข้อ ตรรกะเกมรองรับทันทีโดยไม่ต้องแก้ ส่วนเพดาน
หักคะแนน 30 คุมค่าใช้จ่ายแยกอยู่แล้วตามสเปก

### เพิ่มจากแผน

- **`types.ts`** แยก type ออกจาก reducer ไม่ให้ import วนกัน
- **`instances.ts`** และ **`checkpoint.ts`** — ถ้าไม่ทำตอนนี้ Phase 7 จะเขียนเองเฉพาะกิจ
  ทั้งที่เป็นตรรกะบริสุทธิ์ที่ทดสอบได้เต็ม
- **`feedback.ts`** แยกข้อความ 6 รหัสออกมา พร้อมเทสต์วน 50 ด่านว่าไม่มีข้อความไหนมี
  สูตรหรือชื่อของผลิตภัณฑ์อยู่เลย — ล็อกข้อห้าม "ห้ามเฉลย" ไว้กับเครื่องมือ ไม่ใช่วินัยคน
- **3 event ที่ตารางในสเปกไม่มี** — `USE_HINT` (D-05 บังคับ) และ `PAUSE`/`RESUME`
  (ข้อ 4.5 บังคับให้หยุดนับเวลาเมื่อแท็บถูกซ่อน) ทั้งสามใช้ได้ทุกสถานะระหว่างเล่น
  ไม่ได้เปลี่ยนเส้นทางของ state machine
- **เทสต์เล่นอัตโนมัติครบ 50 ด่าน** ยืนยันว่าทุกด่านเดินจาก `levelIntro` ถึง `levelComplete`
  ได้ 100 คะแนน 3 ดาว — ด่านที่โครงสร้างแปลกจะโผล่ตรงนี้ ไม่ใช่ตอนต่อหน้าจอจริง

### ต่างจากแผน

- **reducer รับ level เป็นอาร์กิวเมนต์** `reduce(state, event, level)` ไม่ให้ reducer เรียก
  `getLevel()` เอง เพราะจะทำให้ `domain/game → data → domain/chemistry` พึ่งพากันเป็นวง
  ใช้ `import type` อย่างเดียว ซึ่งถูกลบทิ้งตอน build
- **event ที่เกี่ยวกับเวลาพก `at` มาเอง** ไม่ให้ reducer เรียก `Date.now()` — reducer จึงยัง
  บริสุทธิ์และเทสต์ไม่ต้องใช้ fake timer
- **event ผิดสถานะคืน state เดิมทั้งอ็อบเจกต์** (`reduce(s, e) === s`) ไม่ใช่สำเนาที่ค่าเท่ากัน
  เพื่อให้ React ไม่ re-render ทุกครั้งที่ผู้เล่นแตะผิดที่ — เทสต์เช็ค identity ไม่ใช่ `toEqual`
- **กดปุ่มที่ควร disabled ไม่นับว่าผิด** — ตรวจก่อนวางครบ กรอกสัมประสิทธิ์ไม่ครบ ยืนยันก่อนตัดครบ
  และเลือกการ์ดที่ตัดไปแล้ว ล้วนคืน state เดิมโดยไม่หักคะแนน เพราะเป็นข้อจำกัดของ UI ไม่ใช่คำตอบผิด
- **`SHOW_IONS` ไม่เปลี่ยน state** เพราะการ์ดไอออนคำนวณจากข้อมูลด่านได้ทั้งหมด ไม่มีอะไรต้องเก็บ
  รับไว้เพื่อให้ Phase 7 สั่งอนิเมชันและ Phase 9 บันทึก event ได้โดยไม่ต้องเลี่ยง state machine
- **`playerProducts()` ประกอบผลิตภัณฑ์ตามลำดับที่ผู้เล่นวาง** ไม่ใช่ลำดับใน `level` เพราะ D-03
  อนุญาตให้วางคู่ตะกอนไว้คู่ที่ 1 หรือ 2 ก็ได้ ถ้าใช้ลำดับของด่านมาตรวจสัมประสิทธิ์
  ผู้เล่นที่วางสลับคู่จะถูกตัดสินว่าผิดทั้งที่ตอบถูก
- **`architecture.test.ts` ตัดคอมเมนต์ก่อนสแกน** — คอมเมนต์ใน `instances.ts` ที่อธิบายว่า
  ทำไม id ต้องคำนวณซ้ำได้ ต้องเอ่ยคำว่า localStorage แล้วกลายเป็นตัวละเมิดกฎเสียเอง
  กฎนี้ห้าม*โค้ด*ที่แตะ storage ไม่ได้ห้าม*เอกสาร*ที่พูดถึงมัน ไม่งั้นคนเขียนจะเลี่ยงไปเขียน
  คำอธิบายที่คลุมเครือซึ่งแย่กว่าเดิม — มีเทสต์พิสูจน์ว่าการตัดคอมเมนต์ไม่ได้ทำให้กฎอ่อนลง

## 4.1 สถานะและ event

```
levelSelect -> levelIntro -> dissociateReactants -> arrangeProductIons
  -> balanceEquation -> validateProducts -> cancelSpectatorIons
  -> netIonicResult -> levelComplete
```

| สถานะ | event ที่รับได้ | เงื่อนไขออก |
|---|---|---|
| `levelIntro` | START_LEVEL, EXIT | ผู้เล่นกดเริ่ม (เริ่มจับเวลาตรงนี้ ไม่ใช่ตอนเข้า route) |
| `dissociateReactants` | SHOW_IONS, CONTINUE | แสดงไอออนสารตั้งต้นครบ |
| `arrangeProductIons` | PLACE_ION, MOVE_ION, REMOVE_ION, CHECK | ช่องครบ 4 และคู่ผลิตภัณฑ์ถูก |
| `balanceEquation` | SET_COEFFICIENT, CHECK_BALANCE | สัมประสิทธิ์ถูกและเป็นอัตราส่วนต่ำสุด |
| `validateProducts` | CONFIRM_PRODUCTS | ตะกอนและผลิตภัณฑ์ที่ละลายถูกต้อง |
| `cancelSpectatorIons` | SELECT_LEFT, SELECT_RIGHT, UNDO, RESET, CONFIRM | ตัดไอออนผู้ชมครบและไม่มีคู่ผิด |
| `netIonicResult` | COMPLETE_LEVEL | สมการสุทธิสมดุลและแสดงผลแล้ว |
| `levelComplete` | NEXT_LEVEL, LEVELS, REPLAY | บันทึกสำเร็จหรือแจ้งข้อผิดพลาดแล้ว |

**ข้ามสถานะ `balanceEquation` ได้** เมื่อสัมประสิทธิ์ทุกตัวเป็น 1 (ด่าน 01-10) ตาม D-04 ให้ transition ตรงไป `validateProducts` แต่ตัว state machine ยังมีสถานะนี้อยู่ เพื่อไม่ให้ตรรกะแตกเป็นสองทาง

## 4.2 รูปร่าง state

```ts
export type GameState = {
  phase: GamePhase;
  levelId: number;
  slots: Array<{ slotId: string; ionInstanceId: string | null }>;
  coefficients: [number | null, number | null, number | null, number | null];
  canceledPairs: Array<{ leftInstanceId: string; rightInstanceId: string }>;
  selection: { side: 'left' | 'right'; instanceId: string } | null;
  hintsUsed: 0 | 1 | 2 | 3;
  wrongAttempts: number;
  errorsByCode: Record<ErrorCode, number>;   // ป้อน Phase 9
  startedAt: number | null;
  elapsedMs: number;
  lastFeedback: Feedback | null;
};
```

`errorsByCode` ใส่ไว้ตั้งแต่ตอนนี้ เพราะงานวิจัยต้องการสถิติว่านักเรียนพลาดเรื่องอะไรบ่อย ถ้าไม่เก็บตั้งแต่แรกจะย้อนกลับมาเก็บไม่ได้

`src/config/scoring.ts` ค่าทั้งหมดต้องอยู่ในไฟล์นี้ไฟล์เดียว ห้าม hard-code ใน component เพื่อให้ผู้วิจัยปรับได้หลังทดลองนำร่อง

```ts
export const SCORING = {

  penaltyPerHint: 10,
  maxHintPenalty: 30,
  minPassScore: 40,
  starThresholds: { three: 90, two: 70, one: 40 },
```

```
score = clamp(
  100 - min(wrongAttempts * 5, 30) - min(hintsUsed * 10, 30),

)
```

## 4.4 ระบบคำใบ้ 3 ระดับ

ตาม D-05 กดได้สูงสุด 3 ครั้งต่อด่าน หัก 10 คะแนนต่อครั้ง

| ระดับ | หน้าที่ | ตัวอย่างด่าน 01 |
|---|---|---|
| 1 | ชี้หลักการกว้าง ๆ | ปฏิกิริยานี้เกิดจากการแลกคู่ระหว่างไอออนบวกกับไอออนลบที่มาจากคนละสาร |
| 2 | ชี้ไอออนที่ควรสนใจ | ลองพิจารณาว่าไอออนเงินจับกับไอออนใดแล้วได้สารที่ไม่ละลายน้ำ |
| 3 | ชี้กฎการละลายที่เกี่ยวข้อง | กฎ เกลือคลอไรด์ละลายน้ำ ยกเว้นเมื่อจับกับ Ag+ หรือ Pb2+ |

ระดับ 3 บอกกฎ แต่ยังไม่บอกสูตรผลิตภัณฑ์ ผู้เล่นต้องประกอบเอง

**ต้องมีเทสต์** ว่าข้อความคำใบ้ทุกข้อไม่มีสูตรของตะกอนอยู่ในนั้น (กฎข้อ 11 ใน Phase 2)

## 4.5 การจับเวลา

- เริ่มนับเมื่อกด START_LEVEL ไม่ใช่ตอนเข้า route
- หยุดนับเมื่อ `document.visibilityState` เป็น hidden แล้วนับต่อเมื่อกลับมา

- refresh กลางด่านแล้วโหลด checkpoint ต้อง**ไม่เพิ่ม `attempts` ซ้ำ**

## กับดักที่ต้องระวัง

| กับดัก | ผลที่ตามมา |
|---|---|
| ใส่ boolean แยกแทน phase เดียว | เกิดสถานะที่เป็นไปไม่ได้ เช่นทั้ง gold และ error พร้อมกัน |
| ให้ reducer เรียก save เอง | ทดสอบยากและเกิด side effect ซ้อน ให้ layer บนเป็นคนเรียก |
| นับเวลาจาก timestamp เริ่มต้น | refresh แล้วเวลากระโดดเป็นชั่วโมง ต้องสะสมเป็น elapsedMs |
| เพิ่ม attempts ตอนโหลด checkpoint | สถิติงานวิจัยเพี้ยน นักเรียนดูเหมือนพยายามเยอะเกินจริง |
| ลืมว่าด่านไม่ต้องดุลก็ต้องผ่าน guard | ถ้า skip แบบ hard-code จะมีสองเส้นทางที่ทดสอบไม่ครบ |
| เก็บ errorsByCode ทีหลัง | ข้อมูลวิจัยที่สำคัญที่สุดหายไปทั้งงาน ย้อนกลับมาเก็บไม่ได้ |
