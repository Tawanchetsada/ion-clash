### บั๊กจริงที่เจอระหว่างทดสอบในเบราว์เซอร์ — ไม่ใช่แค่เขียนโค้ดแล้วเชื่อว่าใช้ได้

เฟสนี้เป็นเฟสแรกที่มีหน้าจอให้เปิดดูจริง และเปิดดูจริงก็เจอบั๊กจริงทันที 4 ข้อ
ซึ่งยืนยันเหตุผลที่แผนบังคับให้ตรวจด้วยตาผ่านเบราว์เซอร์ ไม่ใช่เชื่อผลเทสต์อัตโนมัติอย่างเดียว

**1. Token สีอ้างตัวเองวนไม่รู้จบ** — `globals.css` เดิม (ตั้งแต่ Phase 0) ประกาศ
`--color-navy` ใน `:root` แล้วประกาศซ้ำใน `@theme inline` ว่า `--color-navy: var(--color-navy)`
ซึ่งอ้างถึงตัวเอง `build` ผ่านมาตลอดเพราะไม่เคยมีใครเปิดหน้าเว็บดูจริง แก้โดยยุบเหลือ `@theme`
ชุดเดียวใส่ค่าดิบ — ยืนยันด้วยสายตาว่าสีขึ้นถูกทุกโทเค็นแล้ว

**2. Dialog คืน focus ผิดที่เมื่อมี state อื่นเปลี่ยนระหว่างเปิดอยู่** — โค้ดเดิมให้ effect หลัก
พึ่ง `[open, onClose]` แต่ผู้เรียกส่ง `onClose` เป็น inline arrow function (`() => setOpen(false)`)
ซึ่งเปลี่ยน identity ทุกครั้งที่ parent re-render ไม่ว่าจะด้วยเหตุผลอะไรก็ตาม (นาฬิกา, autosave,
การ์ดอื่นถูกเลือก) ทำให้ effect restart กลางคันแล้วเขียนทับ `previouslyFocused` ด้วย
`document.activeElement` ปัจจุบัน (มักเป็นปุ่มในตัว dialog เอง) พอปิดจริง focus เลยค้างผิดที่
เทสต์เดิมไม่จับได้เพราะ harness มี state เดียว (`open`) การ re-render จึงเกิดพร้อมกับ `open`
เปลี่ยนเสมอ ไม่เคยเกิดแบบ "เปลี่ยนโดยไม่เกี่ยว" — แก้ด้วย pattern "ref เก็บ callback ล่าสุด"
มาตรฐาน (`onCloseRef`) แล้ว effect พึ่ง `[open]` อย่างเดียว พร้อมเทสต์ regression ใหม่ที่จำลอง
ปุ่มนับที่ไม่เกี่ยวกับ dialog เลยเพื่อจับบั๊กนี้ไว้ไม่ให้กลับมา

**3. `AppHeader` ไม่ยอมขึ้นบรรทัดใหม่บนจอแคบ** — เดิมจัดตรา+ป้ายด่าน+เมนูแถวเดียวด้วย
`justify-between` ไม่มี `flex-wrap` ที่ 390px รวมความกว้างเกิน viewport แก้โดยรวมป้ายด่าน
กับเมนูไว้กลุ่มเดียวกันแล้วให้ทั้งแถบ `flex-wrap` ได้

**4. ทั้งหน้าเลื่อนแนวนอนที่ 390px แม้แถบสมการจะตั้งใจให้เลื่อนแค่ตัวเองก็ตาม** — บั๊กที่ลึกและ
สำคัญที่สุด ต้นตอคือ `<body>` ใน `layout.tsx` เป็น `flex flex-col` เสมอ ทำให้ทุกหน้าที่ห่อด้วย
`PageShell` เป็น flex item ของ body โดยอัตโนมัติ และ flex item ที่ไม่กำหนด `min-width` จะขอ
ความกว้างเท่ากับ min-content ของลูกหลานที่กว้างที่สุด — ในที่นี้คือแถบสมการ (`EquationStrip`)
ที่มี `overflow-x:auto` กำกับไว้แล้ว แต่ `overflow-x:auto` เพียงอย่างเดียว **ไม่ทำให้ flex item
หยุดขอความกว้างเกิน** ต้องมี `min-width:0` กำกับด้วยเสมอ — เป็นกับดัก CSS Flexbox ที่รู้จักกันดี
แต่พลาดง่ายมาก แก้ที่ `EquationStrip` (`min-w-0`) และที่ `PageShell` (`w-full min-w-0` — จุดสำคัญ
กว่า เพราะเป็น component จริงที่ทุกหน้าใน Phase 6/7 จะใช้เป็นเปลือกนอก ถ้าไม่แก้ตรงนี้ บั๊กจะ
โผล่ซ้ำทุกหน้าที่มีเนื้อหากว้าง) ยืนยันด้วยการบังคับความกว้างผ่าน JS ก่อนแก้จริงว่าเนื้อหาทั้งหมด
พอดี 390px โดยไม่มี overflow ภายในเลยเมื่อได้ width ที่ถูกต้อง — ทั้งสองจุดมีเทสต์ตรวจ class
`min-w-0`/`w-full` ไว้กันไม่ให้ใครเผลอลบออก

### เสียง — โหลดจริงจาก Kenney แต่เป็น .wav ไม่ใช่ .mp3 ตามที่เอกสารเขียน

ตรวจแล้วพบว่า Kenney แจกต้นฉบับเป็น `.ogg` ล้วน ซึ่ง Safari บน iPad เล่นไม่ได้เลย และเครื่องนี้
ไม่มี ffmpeg จะแปลง ใช้ไฟล์ `.wav` จาก `Calinou/kenney-interface-sounds` (แปลงจากต้นฉบับ
Kenney แบบไม่สูญเสียคุณภาพ, CC0 เหมือนเดิม) แทน แล้วเขียน `scripts/prepare-audio.ts`
ลดขนาดเองด้วย Node ล้วน (mono, ลด sample rate ครึ่งหนึ่งด้วย box filter, ตัดความเงียบหัวท้าย)
ได้ 5 ไฟล์รวม **55.5 KB** (ต่ำกว่างบ 100 KB มาก) สคริปต์ดาวน์โหลดต้นฉบับให้เองถ้ายังไม่มี
ในเครื่อง (`scripts/audio-src/` ไม่ commit เข้า repo เพราะโหลดซ้ำได้เสมอ) ยืนยันไฟล์ไม่ใช่
เสียงเงียบ/พังด้วยการวัดค่า RMS/peak amplitude ก่อนส่งมอบ

  แต่จำเป็นจริง เพราะการ์ดไอออนต้องแสดงสูตร/ชื่อไทย/aria-label ที่มาจาก `getIon()`/`renderIon()`
  ถ้าปล่อยให้ component เรียกเองจะขัด DoD ข้อ "ห้าม import จาก domain/chemistry" ทันที
  ชั้นนี้เป็นคนเดียวที่เรียกโดเมน แล้วส่งต่อเป็น view model แบนราบให้ component วาดอย่างเดียว
- **`CutPairList`** ไม่มีในตารางรายชื่อ component เดิม — เพิ่มเพื่อรองรับข้อบังคับ a11y
  "เส้นตัดไอออนผู้ชมต้องมีรายการข้อความคู่กับเส้น SVG เสมอ" (ข้อ 5.6) ซึ่งเดิมไม่มี component
  รองรับส่วนที่เป็นข้อความเลย
- **`EquationStrip`** แทนที่ `SpectatorConnector` บางส่วน — ส่งมอบสถานะภาพนิ่ง (การ์ดที่ถูกตัด
  ขีดทับ + เลือกได้) ที่ Phase 6 มาวาดเส้น SVG ทับได้เลยโดยไม่ต้องรื้อ
- **หน้า `/dev/components` แยกเป็น 2 ไฟล์** (`page.tsx` server component เช็ค
  `NODE_ENV`+เรียก `notFound()`, `ComponentGallery.tsx` client component ที่มี state
  โต้ตอบได้จริง) แทนที่จะเป็นไฟล์เดียว เพื่อให้ยืนยันได้จริงว่า production build คืน 404 จริง
  (ตรวจแล้วจาก `.next/server/app/dev/components.meta` → `"status": 404`)

### ต่างจากแผน

- **เสียงเป็น `.wav` ไม่ใช่ `.mp3`** ตามที่อธิบายไว้ข้างบน — D-17 ไม่ต้องแก้เพราะยังเป็นเสียง
  Kenney CC0 ชุดเดิม เปลี่ยนแค่นามสกุลไฟล์ตามข้อจำกัดจริงของ Safari/iPad
- **ตรวจ "zoom 200%" ด้วยการลดความกว้าง viewport แทนการซูมเบราว์เซอร์จริง** — เครื่องมือ
  เบราว์เซอร์ที่มีไม่รองรับคำสั่งซูมโดยตรง การลดพื้นที่ให้แคบลง (390/1024/1280px) ทดสอบ
  ปัญหาประเภทเดียวกัน (ข้อความ/เลย์เอาต์ถูกตัดเมื่อพื้นที่ลดลง) — ยังไม่ใช่การยืนยัน zoom 200%
  ตัวจริงทุกหน้า ต้องทำซ้ำใน Phase 10 เมื่อมีหน้าจอจริงครบ 8 route
- **`prefers-reduced-motion` ยังไม่ได้ทดสอบสลับจริงในเบราว์เซอร์เฟสนี้** — กฎ CSS มีอยู่แล้ว
  ตั้งแต่ Phase 0 และไม่ได้แก้ แต่ยังไม่มีแอนิเมชันจริงให้ทดสอบ (แค่ transition สี 150ms
  ตอน hover/focus) การยืนยันเต็มรูปแบบรอ Phase 6 ที่มีแอนิเมชันการ์ด/เส้นตัดจริง
- **เสียงยังไม่ได้ทดสอบบน iPad จริง และปิดจาก `/settings` ไม่ได้** — ยังไม่มีหน้า `/settings`
  (Phase 7) และไม่มีเครื่อง iPad จริงในเฟสนี้ (Phase 6/10) — ส่งมอบเฉพาะไฟล์เสียง +
  `AudioEngine`/`AudioProvider` ที่ปลดล็อกด้วย user gesture และปิดได้ตาม prop `enabled`

## 5.1 ภาษาสีคือภาษาเดียวกันทั้งเกม

จาก UI PDF หน้า 3 สีไม่ใช่การตกแต่ง แต่เป็นการสื่อบทบาทของสาร

| สี | บทบาท | ใช้เมื่อ |
|---|---|---|
| น้ำเงิน `#1F5FAA` | ไอออนบวก | ตลอดเวลา |
| เขียว `#2B8846` | ไอออนลบ | ตลอดเวลา |

| แดง `#C63C45` | คำตอบผิด เส้นตัดผิด | ชั่วคราว |
| กรมท่า `#082541` | header ปุ่มหลัก ข้อความสำคัญ | ตลอดเวลา |

**กติกาที่ห้ามละเมิด**

- **ห้ามใช้สีอย่างเดียวสื่อสถานะ** ต้องมีข้อความ ไอคอน และ `aria-live` ร่วมเสมอ
- แอนิเมชันเปลี่ยนสี 150-250 ms และปิดได้เมื่อ `prefers-reduced-motion: reduce`

## 5.2 EquationView กับการแสดงสูตรเคมี

รับ **FormulaAst** จาก Phase 1 ไม่ใช่สตริง ไม่ใช่ HTML

```tsx
<EquationView ast={ast} ariaLabel="ซิลเวอร์คลอไรด์ สถานะของแข็ง" />
```

| ส่วน | render เป็น |
|---|---|
| `{ kind: 'text' }` | ข้อความปกติ |
| `{ kind: 'sub' }` | `<sub>` ตัวห้อย เช่นเลข 2 ใน H2O |
| `{ kind: 'sup' }` | `<sup>` ตัวยก เช่นประจุ 2+ |

**aria-label ภาษาไทย** ต้องสร้างจาก AST เดียวกัน เช่น `Ag+(aq)` อ่านว่า "ไอออนเงิน ประจุบวกหนึ่ง สถานะสารละลาย" ไม่ใช่ให้ screen reader อ่าน "เอจีพลัสเอคิว"

**บนมือถือ** สมการยาวเกินจอได้ ให้เลื่อนเฉพาะแถบสมการที่มี `overflow-x: auto` และมี affordance ให้เห็นว่าเลื่อนได้ ห้ามให้ทั้งหน้าเลื่อนแนวนอน

| 3 | มือถือแนวนอน | ขั้นต่ำ 667x375 ลดขนาดการ์ด |
| 4 | มือถือแนวตั้ง | เรียงเป็นส่วน ๆ ห้ามบังคับ 16:9 |

- ใช้ CSS Grid และ Flex เท่านั้นสำหรับโครงหลัก หลีกเลี่ยง absolute
- **ห้ามมี horizontal overflow ระดับหน้า** อนุญาตเฉพาะแถบสมการ
- touch target อย่างน้อย 44x44 CSS px
- ใช้ `clamp()` กับขนาดตัวอักษรและการ์ด และคำนึงถึง `safe-area-inset`
- แถวไอออน 4 ใบบนมือถือแนวตั้งแบ่งเป็น 2 แถว แต่**รักษาลำดับซ้ายไปขวา**

## 5.6 Accessibility

- ใช้ `<button>` จริง ห้ามทำปุ่มด้วย `<div>`
- heading เรียงลำดับถูกต้อง ไม่ข้ามระดับ
- feedback ใช้ `aria-live="polite"` · error สำคัญใช้ `role="alert"` อย่างพอดี ไม่ใส่ทุกที่
- รองรับ zoom 200% โดยข้อความไม่ถูกตัดและฟังก์ชันยังใช้ได้
- modal ต้องมี focus trap · ปิดด้วย Escape · คืน focus ไปปุ่มเดิม · มีชื่อ accessible
- เส้นตัดไอออนผู้ชมต้องมี**รายการข้อความ**ของคู่ที่ตัดแล้วควบคู่ไปกับเส้น SVG

## 5.7 เสียง

ตาม **D-17** ใช้ชุดเสียง **CC0** ของ Kenney ซึ่งไม่ต้องให้เครดิต ใช้เชิงพาณิชย์และการศึกษาได้

| แหล่ง | จำนวน | ลิงก์ |
|---|---|---|
| Kenney UI Audio | 50 เสียง | https://kenney.nl/assets/ui-audio |
| Kenney Interface Sounds | 100 เสียง | https://kenney.nl/assets/interface-sounds |

**เสียงที่ต้องใช้ 5 เสียง**

| จังหวะ | ลักษณะเสียงที่เลือก |
|---|---|
| วางการ์ดลงช่อง | คลิกสั้น เบา ไม่รบกวน |
| ตอบถูก | โทนขึ้นสั้น ๆ |
| ตอบผิด | โทนลงต่ำ ไม่ดังจนน่าตกใจ |
| ตะกอนเกิดเป็นการ์ดทอง | เสียงยืนยันที่หนักแน่นกว่าตอบถูกทั่วไป |
| ผ่านด่าน | เสียงสำเร็จสั้น ๆ ไม่เกิน 1.5 วินาที |

**ข้อกำหนดการใช้งาน**

- แปลงเป็น `.webm` หรือ `.mp3` ให้ไฟล์รวมทั้งหมดไม่เกิน 100 KB
- preload ตอนเข้าหน้าเล่นเกม ไม่ใช่ตอนเปิดเว็บ
- เสียงต้องหยุดทันทีเมื่อปิดสวิตช์ใน `/settings`
- **iOS ต้องมี user gesture ก่อนเล่นเสียงครั้งแรก** ให้ปลดล็อก AudioContext ตอนผู้เล่นกดปุ่มเริ่มเกม ไม่งั้นเสียงจะเงียบทั้งเกมบน iPad
- เสียงเป็นส่วนเสริมเท่านั้น ห้ามใช้เสียงเป็นช่องทางเดียวในการสื่อสถานะ

**เพลงพื้นหลัง** ตั้งค่าเริ่มต้นเป็น **ปิด** เพราะเป็นสื่อที่ต้องใช้สมาธิ ผู้เล่นเปิดเองได้ ถ้าจะใส่ให้เลือกเพลงบรรเลงเบาที่เป็น CC0 จาก OpenGameArt
