# แผนพัฒนา Ion Clash Web

เอกสารชุดนี้แตกงานสร้างเว็บเกม Ion Clash ออกเป็น 12 phase เรียงตามลำดับที่ต้องทำจริง
ทุก phase มีเงื่อนไขเข้า–ออกชัดเจน เพื่อให้ตรวจสอบได้ว่า "เสร็จ" แปลว่าอะไร

## Definition of Done ของทั้งโปรเจกต์

อ้างจาก spec หัวข้อ "Definition of Done" — ทุกข้อต้องผ่านก่อนถือว่าส่งมอบ

- [ ] `npm run lint` · `npm run typecheck` · `npm test` · `npm run build` ผ่านทั้งหมด
- [ ] ข้อมูล 50 ด่านผ่าน chemistry/data validation อัตโนมัติ
- [ ] ผู้ตรวจเนื้อหาเคมีอนุมัติสมการและสถานะของสารครบ 50 ด่าน
- [ ] ทดสอบจริงบน Safari iPad อย่างน้อย 1 รอบ
- [ ] ไม่มี console error ทั้ง happy path และ error path
- [ ] Save schema มี version, migration test, export/import และ reset
- [ ] README ระบุวิธี run, test, build, deploy และวิธีแก้ข้อมูลด่าน

## หมายเหตุการใช้เอกสารชุดนี้

ทุก phase เขียนแบบ "อ่านแล้วลงมือได้เลย" — มีลำดับขั้นการทำงาน รายชื่อไฟล์ที่จะสร้าง เงื่อนไขผ่าน และกับดักที่ต้องระวัง
ถ้าระหว่างทางพบว่าข้อตัดสินใจใดใช้ไม่ได้จริง ให้แก้ที่ `00-decisions.md` ก่อน แล้วค่อยแก้ phase ที่เกี่ยวข้อง

## กติกาสำหรับผู้ที่มาทำต่อ (คนหรือ agent)

**อ่านก่อนแตะโค้ดทุกครั้ง** — `CLAUDE.md` ที่รากโปรเจกต์ · `00-decisions.md` (D-01 … D-21) · และไฟล์ phase ที่กำลังทำ
ข้อตัดสินใจใน `00-decisions.md` ตกลงกันแล้วพร้อมเหตุผล **ห้ามเปลี่ยนโดยไม่บันทึก**

**ทำทีละเฟส ไม่ข้าม** เฟสหลังพึ่งของที่เฟสก่อนสร้างไว้ตามคอลัมน์ "ต้องรออะไร" ในตารางข้างบน

**ห้ามทำสิ่งเหล่านี้ในทุกเฟส** (ย่อจาก "ข้อห้ามสำหรับ Agent" ในสเปก — ฉบับเต็มอยู่ใน `CLAUDE.md`)

- ห้ามคิดหรือแก้สมการเคมีเอง — 50 ด่านร่างไว้แล้วและรอลายเซ็นอาจารย์
- ห้ามเขียนค่าที่คำนวณได้ลง `levelSeeds.ts` — seed มีแค่ `id` `difficulty` และไอออนสองคู่
- ห้ามอ่าน `localStorage` ตอน SSR หรือใน Server Component
- ห้ามกันด่านที่ล็อกด้วย CSS หรือปุ่มสีเทาอย่างเดียว ต้องมี route guard จริง
- ห้ามทาสีทองก่อนตรวจครบทั้งสูตร ประจุ สถานะ และการดุล
- ห้ามทำ interaction ที่ใช้ได้เฉพาะการลาก — ต้องมีครบ 3 ทางเสมอ
- ห้ามสื่อสารสถานะด้วยสีอย่างเดียว ต้องมีข้อความและไอคอนคู่กัน
- ห้ามเฉลยคำตอบในข้อความ error — บอกหลักการที่ผิด (`E-CHARGE` `E-PAIR` `E-PHASE` `E-BALANCE` `E-RATIO` `E-SPECTATOR`)

## ขั้นตอนปิดเฟส — เหมือนกันทุกเฟส

1. **ประตู 4 บาน** ต้องผ่านครบก่อนคิดจะ commit

   ```bash
   npm run lint && npm run typecheck && npm test && npm run build
   ```

2. **`npm run test:e2e` ต้องผ่าน** (ตั้งแต่ Phase 6 เป็นต้นไป ที่โฟลเดอร์ `e2e/` เริ่มมีของ)
3. **เปิดดูด้วยตาจริงในเบราว์เซอร์** ที่ 1024×768 · 1280×720 · 390×844 — เทสต์เขียวไม่ได้แปลว่าหน้าจอถูก
   (Phase 5 เจอบั๊กจริง 4 ข้อด้วยวิธีนี้ ซึ่งเทสต์อัตโนมัติทั้งหมดจับไม่ได้เลยสักข้อ)
4. **เขียนบล็อก "สถานะ: เสร็จแล้ว ✅" ไว้ต้นไฟล์ phase นั้น** ระบุอย่างน้อย
   - ไฟล์ที่สร้างและแก้
   - จำนวนเทสต์ก่อน → หลัง
   - **บั๊กจริงที่เจอ** พร้อมต้นเหตุและวิธีแก้ (ส่วนที่มีค่าที่สุดสำหรับคนที่มาทำต่อ)
   - "เพิ่มจากแผน" และ "ต่างจากแผน" — เขียนตามความจริง ไม่ใช่เขียนให้ตรงแผน
   - ดูรูปแบบจาก `06-phase-5-design-system.md` ซึ่งเป็นตัวอย่างที่สมบูรณ์ที่สุด
5. **อัปเดต 2 ที่เสมอ** — แถวสถานะในไฟล์นี้ และย่อหน้าสถานะใน `CLAUDE.md`
6. **commit + push แล้วรอ CI เขียว** ก่อนขึ้นเฟสถัดไป

**หลังแตะ dependency ทุกครั้ง** ต้องทำพิธีนี้ ไม่งั้น CI ตายที่ `npm ci` (เคยเกิดแล้ว 2 ครั้ง)

```bash
rm -rf node_modules package-lock.json && npm install && npm ci --dry-run
```
