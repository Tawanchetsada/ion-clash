# Phase 6 · ระบบลาก-วางและการตัดไอออน

> **เป้าหมาย:** ผู้เล่นทำทุกอย่างได้ครบด้วย 3 วิธี คือลาก แตะ และคีย์บอร์ด บน iPad จริง
> **ต้องรอ:** Phase 5
> **กฎเหล็กจาก spec:** ห้ามพึ่ง HTML5 drag-and-drop อย่างเดียว เพราะประสบการณ์ touch บน iPad ไม่สม่ำเสมอ

นี่คือ phase ที่เสี่ยงที่สุดของโปรเจกต์ ถ้าลากไม่ได้บน iPad งานวิจัยล้มทั้งงาน จึงต้องทดสอบบนเครื่องจริงตั้งแต่ต้น phase ไม่ใช่ตอนท้าย

## 6.1 สามเส้นทางที่ต้องทำงานเท่าเทียมกัน

| วิธี | ขั้นตอน | กลุ่มผู้ใช้ |
|---|---|---|
| **ลาก** | กดค้างที่การ์ด ลากไปช่อง ปล่อย | iPad และเมาส์ |
| **แตะสองครั้ง** | แตะการ์ดให้ selected แล้วแตะช่องปลายทาง | iPad ที่ลากไม่ถนัด นิ้วเล็ก |
| **คีย์บอร์ด** | Tab เลือกการ์ด · Enter หรือ Space ถือ · ลูกศรเลือกช่อง · Enter วาง · Escape ยกเลิก | Desktop และผู้ใช้ screen reader |

ทั้งสามทางต้องส่ง event เดียวกันเข้า reducer คือ `PLACE_ION` ไม่ใช่มีตรรกะแยกกันสามชุด

## 6.2 ใช้ Pointer Events ไม่ใช่ HTML5 DnD

```
pointerdown   -> จับ pointerId ไว้ เริ่มจับระยะ
pointermove   -> ถ้าเลื่อนเกิน threshold 8px จึงเริ่มโหมดลาก
                 (ต่ำกว่านั้นถือเป็นการแตะ)
pointerup     -> หา drop target ที่อยู่ใต้ตำแหน่ง แล้ว PLACE หรือคืนที่เดิม
pointercancel -> คืนการ์ดกลับที่เดิมเสมอ
```

**ต้องทำ**

- `setPointerCapture` เพื่อไม่ให้ลากหลุดเมื่อนิ้วออกนอกการ์ด
- `touch-action: none` บนการ์ด กันไม่ให้ Safari เลื่อนหน้าจอแทนการลาก
- ghost preview ตามนิ้ว และ highlight ช่องที่รับได้
- **ไม่ซ่อนการ์ดต้นทางถาวร**จนกว่าจะวางสำเร็จ ลากพลาดต้องคืนที่เดิม

> `touch-action: none` คือบรรทัดที่คนลืมบ่อยที่สุด ถ้าไม่ใส่ การลากบน iPad จะกลายเป็นการ scroll หน้าจอ

---

## 6.3 การจัดการ focus

หลังวางสำเร็จ focus ต้องย้ายไปยังช่องที่วาง เพื่อให้ screen reader ประกาศผล

| เหตุการณ์ | focus ไปที่ | ประกาศว่า |
|---|---|---|
| วางสำเร็จ | ช่องที่วาง | "วางไอออนเงินในช่องที่ 1 แล้ว" |
| วางไม่สำเร็จ | การ์ดต้นทาง | "ช่องนี้รับไม่ได้ ไอออนกลับที่เดิม" |
| เอาออกจากช่อง | การ์ดที่กลับไป | "นำไอออนเงินออกจากช่องที่ 1" |
| ตรวจแล้วผิด | FeedbackPanel | ข้อความ error ผ่าน `role="alert"` |

## 6.4 SpectatorConnector

เส้นตัดสีแดงเชื่อมการ์ดซ้ายกับขวา วาดเป็น SVG overlay

**การคำนวณตำแหน่ง**

- อ่านตำแหน่งจริงของการ์ดด้วย `getBoundingClientRect()` ผ่าน ref
- คำนวณใหม่เมื่อขนาดเปลี่ยน ด้วย `ResizeObserver` ห่อด้วย `requestAnimationFrame`
- เก็บพิกัดไว้ใน state ของ component เท่านั้น **ห้ามบันทึกลง checkpoint** (Phase 3)

**บนมือถือที่สมการขึ้นบรรทัดใหม่** เส้นจะพาดข้ามบรรทัดแล้วดูมั่ว ทางแก้

1. ถ้าการ์ดคู่กันอยู่คนละบรรทัด ให้วาดเส้นโค้งอ้อมแทนเส้นตรง
2. **และ**แสดงรายการข้อความคู่ที่ตัดแล้วเสมอ เช่น "ตัดแล้ว Na+ ทั้งสองข้าง" เพื่อไม่ต้องพึ่งเส้นอย่างเดียว

**กติกาการตัด**

- เลือกไอออนฝั่งซ้าย 1 ใบ แล้วเลือกชนิดเดียวกันฝั่งขวา 1 ใบ
- จับคู่ด้วย `ionId + charge + phase + count` ห้ามเทียบสตริง
- ห้ามตัดไอออนที่เกิดตะกอน หรือที่ปรากฏไม่เท่ากันสองข้าง
- มี **Undo คู่ล่าสุด** และ **Reset ทั้งหมด**
- ปุ่มยืนยันเปิดใช้เมื่อตัดครบและไม่มีคู่ผิด

## 6.5 แอนิเมชันที่ต้องมี

| จังหวะ | ผล | เวลา |
|---|---|---|
| การ์ดลงช่องสำเร็จ | ขยายแล้วหดกลับเล็กน้อย | 150 ms |
| ตอบผิด | การ์ดสั่นแนวนอนและขอบแดง | 200 ms |
| ไอออนสองใบรวมเป็นตะกอน | เลื่อนเข้าหากันแล้วเปลี่ยนเป็นการ์ดทอง | 250 ms |
| เส้นตัดปรากฏ | วาดจากซ้ายไปขวา | 200 ms |
| ผ่านด่าน | การ์ดทองเรืองแสงหนึ่งครั้ง | 250 ms |

ทั้งหมดต้องหยุดทำงานเมื่อ `prefers-reduced-motion: reduce` หรือเมื่อผู้ใช้ปิดใน `/settings`

## กับดักที่ต้องระวัง

| กับดัก | ผลที่ตามมา |
|---|---|
| ลืม `touch-action: none` | ลากบน iPad กลายเป็น scroll เล่นไม่ได้เลย |
| ไม่ใช้ `setPointerCapture` | ลากเร็ว ๆ แล้วการ์ดหลุดกลางทาง |
| ใช้ `onMouseDown` แทน `onPointerDown` | touch ไม่ทำงาน |
| threshold 0px | แตะธรรมดากลายเป็นการลาก ผู้เล่นเลือกการ์ดไม่ได้ |
| คำนวณเส้น SVG ทุก frame | iPad รุ่นเก่ากระตุก ต้องคำนวณเมื่อขนาดเปลี่ยนเท่านั้น |
| ทดสอบแค่ Chrome DevTools touch emulation | ไม่เจอปัญหาจริงของ Safari ต้องลองเครื่องจริงอย่างน้อยหนึ่งรอบใน phase นี้ |
| ซ่อนการ์ดต้นทางทันทีที่เริ่มลาก | ลากพลาดแล้วการ์ดหายไปเลย ผู้เล่นตกใจ |
